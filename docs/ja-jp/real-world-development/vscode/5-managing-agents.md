GitHub Copilot をエージェントモードで使うと、コードベースを調査し、変更を提案してファイルを編集し、コマンドを実行します。VS Code の Copilot Chat では、ローカル環境でエージェントが実行するツール呼び出しやファイル編集をリアルタイムで確認できます。差分をインラインでレビューし、変更を個別に承認または取り消し、フォローアッププロンプトでエージェントを誘導して、エディターを離れずに作業を改善・拡張できます。

この演習では、次のことを行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして承認します。
- 実行中のセッションに指示を送り、高コントラストモードに加えてライトモードを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ用カスタムエージェントが、高コントラストモードを実装しています。作業中にデザインチームから追加の依頼がありました。既定のテーマが暗すぎると感じる利用者向けに、ライトモードの切り替えも追加します。新しい会話を始める代わりに、現在のセッションを誘導して作業を拡張します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが調査するファイル、実行するコマンド、提案する編集など、作業の各手順が表示されます。各ファイルの編集は差分と **Keep** / **Undo** の操作とともにチャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントが作業している間、チャットをスクロールしてツールの実行を確認します。ファイルの読み取りや編集、実行を求めるターミナルコマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がインライン表示されます。
   - **Keep** を選択すると変更を承認します。
   - **Undo** を選択すると変更を取り消し、エージェントに再度作業させます。
4. チャット上部の **Files changed** 表示を開くと、セッション中にエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ターミナルコマンドの実行などに許可が必要な場合、エージェントは一時停止して **Allow** を表示します。内容を確認し、許可してもよいコマンドだけ承認してください。

5. エージェントが高コントラストモードの実装を終えるまで待ちます。変更内容をまとめた最終メッセージが表示されます。

## ライトモードを追加するようエージェントに指示する

高コントラストモードができたら、同じ会話を続けてライトモードの切り替えを追加します。同じチャットセッションを使うため、エージェントは変更したコンポーネント、スタイルの設計方法、設定の保存方法など、前の作業のコンテキストを保っています。

1. Copilot Chat の入力欄に次のフォローアッププロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントがこれまでの変更を確認し、ライトモードの追加を提案する様子を確認します。
3. 高コントラストモードのときと同じように、新しい編集を1つずつレビューし、各差分で **Keep** または **Undo** を選択します。
4. エージェントの進め方が希望と異なる場合 (例: 切り替え UI を意図せずリファクタリングする場合) は、チャット入力欄の横にある **Stop** ボタンで停止して、追加の説明を送ります。

> [!TIP]
> 実行中のセッションを誘導すると、最初からやり直すより短時間で済みます。フォローアッププロンプトで、調整 (「CSS を簡潔にして、セレクターの重複ではなく CSS 変数を使う」)、修正 (「3つ目の切り替えを追加せず、既存の設定パネルにライトモードを組み込む」)、範囲の拡張 (「両方の切り替えにキーボードショートカットも追加する」) を依頼できます。

## 変更内容をレビューする

作業をコミットする前に、エージェントが変更したファイル全体を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタムエージェントがガイドしたアクセシビリティのパターン (Accessible Rich Internet Applications (ARIA) 属性、キーボード操作、セマンティック HTML、local storage による設定の保存) が反映されていることを確認します。
4. 問題がなければ、Source Control パネルで変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードで、進行中のセッションを監視して方向付けました。ファイルの編集を確認しながら承認または取り消し、コンテキストを保ったままフォローアッププロンプトで作業を拡張しました。

このレッスンでは、次のことを行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個々のファイル編集を承認または取り消しました。
- フォローアッププロンプトで実行中のセッションを誘導しました。

[次のレッスン][next-lesson]では、アクセシビリティの変更をプルリクエストとして公開し、このラボ全体でローカルのカスタムエージェントが作成した変更をレビューします。
